# 协议手册

线上格式只有一个定义处：[crates/protocol/src/lib.rs](../crates/protocol/src/lib.rs)。
服务端、客户端、`probe` 都从那里取编解码，改一处三端同时变。

---

## 1. 帧

```
┌──────────┬────────┬───────────────┐
│ 4B 长度  │ 1B 类型 │    payload     │
│  big-end │        │               │
└──────────┴────────┴───────────────┘
长度 = 1 + payload.len()，且 ≤ 32768（含类型字节）
```

- 长度 0、超过上限、或与实际收到的字节数不符 → 丢弃连接。
- 没有魔数、没有版本字段；`HELLO` 的返回值说明对端版本（当前 **4**）。
- 公开站在帧层之下加 TLS（自签证书 + 客户端按指纹固定）；回环服务可明文。
- 普通请求是「一连接一请求一响应」；`ImageStream` 在同一连接里连续返回多个 `IMAGE` 分片。

### 版本历史

| 版本 | 变化 |
|---|---|
| 2 → 3 | `MANIFEST` 增加路径字段，页面从「按页号」变成「按路径」 |
| 3 → 4 | `HELLO` 增加站点名；新增 `RESOLVE` / `RESOLVED`（站点解析） |

v3 的老客户端遇到 v4 服务端：`HELLO` 解析会失败（多了一个字段），但 `MANIFEST` / `PAGE`
不受影响——所以它仍能看公开站，只是拿不到站点名。v4 客户端遇到 v3 服务端同理。

## 2. 类型

| 值 | 名称 | 方向 | payload |
|---|---|---|---|
| `0x01` | `REQ` | 客户端 → 服务端 | `16B 会话` + `u8 op` + 参数 |
| `0x02` | `SUBMIT` | 客户端 → 服务端 | `16B 会话` + `u16 页号` + `u16 字段数` + N × (`u8 名长`, 名, `u32 值长`, 值) |
| `0x81` | `MANIFEST` | 服务端 → 客户端 | `16B 会话` + `u16 条数` + N × (`u16 页号`, `u8 标志`, `u64 哈希`, `u16 标题长`, 标题, `u16 路径长`, 路径) |
| `0x82` | `PAGE` | 服务端 → 客户端 | `u16 页号` + `u32 总长` + `u32 偏移` + `u32 本片长` + 字节 |
| `0x83` | `IMAGE` | 服务端 → 客户端 | 同上 |
| `0x84` | `EMPTY` | 服务端 → 客户端 | 16 字节 0 |
| `0x85` | `HELLO` | 服务端 → 客户端 | `u16 版本` + `u16 名长` + 站点名 |
| `0x86` | `RESOLVED` | 服务端 → 客户端 | `u16 名长` 名字 + `u16 端长` 端点 + `u8 是否 TLS` + `u16 标题长` 标题 |

`REQ` 的 op：

| op | 参数 | 含义 |
|---|---|---|
| `0` | — | 取清单 |
| `1` | `u16 页号` | 取页 |
| `2` | `u16 图号` + `u32 偏移` | 取一个图片分片 |
| `3` | — | 版本握手，返回 `HELLO` |
| `4` | `u16 图号` + `u32 偏移` | 从偏移起在同一连接流式返回全部分片 |
| `5` | `u16 名长` + 站点名 | 问「另一个站住在哪」，返回 `RESOLVED`；不知道就回 `EMPTY` |

`MANIFEST` 条目的标志位：bit0 = 动态页。
`u64 哈希` 是页面内容的 FNV-1a 64 位值（动态页用源码，静态页用预渲染输出），
客户端用它判断静态页缓存是否还有效。
`路径` 是给读者看的地址（如 `/`、`/notes/`），客户端用它解析地址栏；页号仍是协议内部标识。

**所有失败都回 `EMPTY`**：页面不存在、Python 崩溃、超时、清单读不到、站名不知道……
客户端只能知道「没拿到」，具体原因写在服务端日志里。

## 3. 站点解析（`op 5`）

客户端只内置一小份种子表（`nac.routes` 或编译期嵌入）。
遇到表里没有的 `名字.后缀` 时，它向**当前所在的服务器**发一次 `op 5`。

服务器从自己的 `sites.json` 回答：

```json
{
  "home": {"host": "199.7.140.217", "port": 7000, "tls": true,  "title": "演示站"},
  "shop": {"host": "199.7.140.217", "port": 7002, "tls": true,  "title": "商店"}
}
```

- contentd 用 `--registry <文件>` 指定它，用 `--name <名字>` 说明自己叫什么。
- 客户端把答案记进内存里的表，本次运行内不再重复询问。
- 回答里带 `tls` 标志，客户端据此决定这条连接要不要套 TLS。
- 所有公开站**必须共用同一张证书**：客户端的 pin 是全局单个的。

### 为什么每个站都能回答

如果只有中心站能回答，这套东西永远是一个中心 + 一堆叶子。
让每个站读自己的注册表之后，网络可以靠站点互相认识长出去：

```
机器 A  sites.json: {a, b}       A 认识 B
机器 B  sites.json: {b, c}       B 认识 C
```

从 A 进来的人能到 B，从 B 再出发就能到 C，谁都不需要一份全网总表。

代价是服务器可以引荐任意地址。在单人运营的前提下这是可接受的；
要允许第三方站点进入，这条回答就需要签名。

### 显示后缀

`nac.local` 只是默认值，不参与任何真实解析，只用来把「站点名」和「路径」分开。
想换就在 `nac.routes` 里写一行（也支持 `NAC_DOMAIN` 环境变量覆盖）：

```
@domain shop.example
```

改了之后地址栏显示 `shop.example/`，`名字.shop.example/` 也照常解析。

## 4. 尺寸与分片

| 项 | 限制 |
|---|---|
| 帧 | ≤ 32768 字节 |
| 单页正文 | ≤ 16384 字节（`CHUNK`） |
| 页面 stdout | ≤ 128 KB（超出视为失败） |
| 页面 stderr 采集 | ≤ 8 KB（只进日志） |
| 页面执行 | ≤ 2 秒 |
| 并发连接 | 32（超出直接断连） |
| 会话号 | 16 字节 |

图片分片同样走 16384 字节上限；客户端用 `op 2` 反复取偏移直到 `本片长` 为 0，
或用 `op 4` 一次连接取完。

## 5. 会话

- 会话号是 `16B`，由客户端在请求里带上；全 0 表示「还没有」。
- 服务端对未知会话**分配一个新的**，并在 `MANIFEST` 的响应里带回。
- 会话文件在 `data/state/sessions/<hex>.json`，静默超过 TTL（默认 168 小时）就被清理。
- 会话只用于页面自己的临时状态，服务端不据此识别或统计任何人。

## 6. 页面执行契约

页面在 `contentd` 里执行，契约是环境变量 + stdout：

| 环境变量 | 含义 |
|---|---|
| `NAC_PAGE` | 当前页号 |
| `NAC_INPUT` | JSON：`{"page": N, "fields": {...}}` |
| `NAC_SESSION_FILE` | 会话状态文件路径 |
| `NAC_DATA_DIR` | 站点私有目录 |
| `NAC_STATIC` | 为 `1` 表示这是发布时预渲染，`nac` 据此拒绝有副作用的接口 |
| 其他 | `contentd --env K=V` 传进来的额外变量（运营台用 `NAC_ROOT`、`NAC_LOG`） |

- 进程以 `python3 -B -X utf8` 启动，工作目录是该代的 `scripts/`。
- **stdout 就是页面内容**；第一个非空白行是 `@@REDIRECT <页号>` 时，服务端改发那一页。
- stderr 只进服务端日志，不会到客户端。
- 没有常驻内存：每次请求都是新进程，状态只能放 `data_dir()` 或会话文件。

## 7. 地址栏语法

客户端接受的写法（`后缀` 来自 `@domain`，默认 `nac.local`）：

| 输入 | 结果 |
|---|---|
| `后缀/`、`/`、空 | 当前站首页 |
| `后缀/about`、`/about`、`about` | 当前站的路径 |
| `名字.后缀/路径` | 切到该站 |
| `名字/路径` | 同上（裸名字） |
| `nac://名字/路径` | 同上（旧写法，仍支持） |
| `名字/7` | 旧写法，按内部页号解析 |

**真实主机地址被拒绝**：`127.0.0.1:7000/`、`example.test/` 一律视为无效地址。
端点只存在于 `nac.routes` 与服务器的回答里，用户既看不到也不必输。

这是遮掩，不是加密：客户端要直连就必须知道端点，能翻文件的人总能拿到。
