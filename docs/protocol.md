# 协议手册

线上格式只有一个定义处：[crates/protocol/src/lib.rs](../crates/protocol/src/lib.rs)。
服务端、客户端、`probe` 都从那里取编解码，改一处三端同时变。

当前版本 **5**。

---

## 1. 帧

```
┌──────────┬────────┬───────────────┐
│ 4B 长度  │ 1B 类型 │    payload     │
│  big-end │        │               │
└──────────┴────────┴───────────────┘
长度 = 1 + payload.len()，且 ≤ 32768（含类型字节）
```

- 长度 0、超过上限、或与实际收到的字节数不符 → 丢弃连接。
- 没有魔数、没有版本字段；`HELLO` 的返回值说明对端版本。
- 公开站在帧层之下加 TLS（自签证书 + 客户端按指纹固定）；回环服务可明文。
- 普通请求是「一连接一请求一响应」；`ImageStream` 在同一连接里连续返回多个 `IMAGE` 分片。

### 版本历史

| 版本 | 变化 |
|---|---|
| 2 → 3 | `MANIFEST` 增加路径字段，页面从「按页号」变成「按路径」 |
| 3 → 4 | `HELLO` 增加站点名；新增 `RESOLVE` / `RESOLVED`（站点解析） |
| 4 → 5 | 每个请求带上 `path`（前缀页要知道自己回答的是哪个地址）；`MANIFEST` 每项增加 `match` 前缀 |

**v5 与 v4 不兼容**：v4 客户端发的帧少了 `path` 字段，v5 服务端会判成畸形并回 `EMPTY`。
两端要么一起升，要么一起不升。

## 2. 类型

| 值 | 名称 | 方向 | payload |
|---|---|---|---|
| `0x01` | `REQ` | 客户端 → 服务端 | `16B 会话` + `u16 路径长` + 路径 + `u8 op` + 参数 |
| `0x02` | `SUBMIT` | 客户端 → 服务端 | `16B 会话` + `u16 路径长` + 路径 + `u16 页号` + `u16 字段数` + N × (`u8 名长` 名 `u32 值长` 值) |
| `0x81` | `MANIFEST` | 服务端 → 客户端 | `16B 会话` + `u16 条数` + N × 条目 |
| `0x82` | `PAGE` | 服务端 → 客户端 | `u16 页号` + `u32 总长` + `u32 偏移` + `u32 本片长` + 字节 |
| `0x83` | `IMAGE` | 服务端 → 客户端 | 同上 |
| `0x84` | `EMPTY` | 服务端 → 客户端 | 16 字节 0 |
| `0x85` | `HELLO` | 服务端 → 客户端 | `u16 版本` + `u16 名长` + 站点名 |
| `0x86` | `RESOLVED` | 服务端 → 客户端 | `u16 名长` 名字 + `u16 端长` 端点 + `u8 是否 TLS` + `u16 标题长` 标题 |

`MANIFEST` 的一个条目：

```
u16 页号 | u8 标志 | u64 哈希 | u16 标题长 标题 | u16 路径长 路径 | u16 前缀长 前缀
```

- `标志` bit0 = 动态页
- `哈希` 是内容的 FNV-1a 64 位值（动态页用源码，静态页用预渲染输出）
- `路径` 是给读者看的地址（`/`、`/notes/`），客户端用它解析地址栏
- `前缀` 是 `# nac:match` 声明的地址族（`/item/`），没有就是空串

`REQ` 的 op：

| op | 参数 | 含义 |
|---|---|---|
| `0` | — | 取清单 |
| `1` | `u16 页号` | 取页 |
| `2` | `u16 图号` + `u32 偏移` | 取一个图片分片 |
| `3` | — | 版本握手，返回 `HELLO` |
| `4` | `u16 图号` + `u32 偏移` | 从偏移起在同一连接流式返回全部分片 |
| `5` | `u16 名长` + 站点名 | 问「另一个站住在哪」，返回 `RESOLVED`；不知道就回 `EMPTY` |

**所有失败都回 `EMPTY`**：页面不存在、Python 崩溃、超时、清单读不到、站名不知道……
客户端只能知道「没拿到」，具体原因写在服务端日志里。

## 3. 站点解析（`op 5`）

客户端只内置一小份种子表（`nac.routes` 或编译期嵌入）。
遇到表里没有的名字时，它向**当前所在的服务器**发一次 `op 5`。

**名字就是一整串字符**：`nac.local`、`iris.out`、`EX_MYTH` 地位相同，没有后缀、
没有层级。客户端只做「查表 / 问人」两件事，不解析、不推导。

服务器从自己的 `sites.json` 回答：

```json
{
  "nac.local": {"host": "199.7.140.217", "port": 7000, "tls": true, "title": "主站"},
  "iris.out":  {"host": "199.7.140.217", "port": 7003, "tls": true, "title": "iris.out"}
}
```

- contentd 用 `--registry <文件>` 指定它，用 `--name <名字>` 说明自己叫什么。
- 查表不分大小写；回答里的 `name` 是**表里的写法**，客户端据此把地址栏统一成它。
- 客户端把答案记进内存里的表，本次运行内不再重复询问。
- 回答里带 `tls` 标志，客户端据此决定这条连接要不要套 TLS。
- 所有公开站**必须共用同一张证书**：客户端的 pin 是全局单个的。

### 为什么每个站都能回答

如果只有中心站能回答，这套东西永远是一个中心 + 一堆叶子。
让每个站读自己的注册表之后，网络可以靠站点互相认识长出去：

```
机器 A  sites.json: {a, b}       A 认识 B
机器 B  sites.json: {b, c}       B 认识 C
```

从 A 进来的人能到 B，从 B 再出发就能到 C，谁都不需要一份全网总表。

代价是服务器可以引荐任意地址。在单人运营的前提下这是可接受的；
要允许第三方站点进入，这条回答就需要签名。

### 什么算一个名字

字母、数字、点、连字符、下划线，最长 64；不能有空白，也不能有 `:`（那是端点，
不是地址，客户端会直接拒绝而不是当成路径）。

所以 `EX_MYTH` 这种在真域名系统里非法的写法在这里完全正常 —— 名字只是用来查表的
一串字符，没有任何一部分参与真实解析。

单看客户端有没有把某个词当名字：**带点或下划线才算**。所以 `about` 是路径，
`iris.out` 是名字；表里恰好有个叫 `about` 的站时，表优先。

## 4. 尺寸与分片

| 项 | 限制 |
|---|---|
| 帧 | ≤ 32768 字节 |
| 单页正文 | ≤ 16384 字节（`CHUNK`） |
| 页面 stdout | ≤ 128 KB（超出视为失败） |
| 页面 stderr 采集 | ≤ 8 KB（只进日志） |
| 页面执行 | ≤ 2 秒 |
| 并发连接 | 32（超出直接断连） |
| 会话号 | 16 字节 |

图片分片同样走 16384 字节上限；客户端用 `op 2` 反复取偏移直到 `本片长` 为 0，
或用 `op 4` 一次连接取完。

**清单受 32 KB 帧上限约束**：300 页短标题约 9 KB，500 页 20 字标题约 47 KB —— 后者
直接超过上限，整站不可读。页面多到那个程度要分站点，不是分页。

## 5. 会话

- 会话号是 `16B`，由客户端在请求里带上；全 0 表示「还没有」。
- 服务端对未知会话**分配一个新的**，并在 `MANIFEST` 的响应里带回。
- 会话文件在 `data/state/sessions/<hex>.json`，静默超过 TTL（默认 168 小时）就被清理。
- 会话只用于页面自己的临时状态，服务端不据此识别或统计任何人。

## 6. 页面执行契约

页面在 `contentd` 里执行，契约是环境变量 + stdout：

| 环境变量 | 含义 |
|---|---|
| `NAC_PAGE` | 当前页号 |
| `NAC_PATH` | 本次请求的地址（前缀页靠它取参数） |
| `NAC_INPUT` | JSON：`{"page": N, "path": "/x", "fields": {...}}` |
| `NAC_SESSION_FILE` | 会话状态文件路径 |
| `NAC_DATA_DIR` | 站点私有目录 |
| `NAC_STATIC` | 为 `1` 表示发布时预渲染，`nac` 据此拒绝有副作用的接口 |
| 其他 | `contentd --env K=V` 传进来的额外变量（运营台用 `NAC_ROOT`、`NAC_LOG`） |

- 进程以 `python3 -B -X utf8` 启动，**工作目录是该代的 `scripts/`**（静态页、动态页一致）
- **stdout 就是页面内容**；第一个非空白行是 `@@REDIRECT <页号> <地址>` 时，服务端改发
  那一页，并把地址带过去（前缀页否则会退化）
- `nac.py` 会把 `sys.stdout` 换到 stderr，所以页面里的 `print()` 只进日志
- stderr 只进服务端日志，不会到客户端
- 没有常驻内存：每次请求都是新进程，状态只能放 `data_dir()` 或会话文件

## 7. 地址栏语法

| 输入 | 结果 |
|---|---|
| `/`、空 | 当前站首页 |
| `/about`、`about` | 当前站的路径 |
| `nac.local/路径` | 切到该站（表里有就直接用） |
| `iris.out/路径`、`EX_MYTH/` | 同上；表里没有就问当前服务器 |
| `nac://名字/路径` | 同上（旧写法，仍支持） |
| `名字/7` | 旧写法，按内部页号解析 |

判断只有三步：**表里有就用 → 像名字（带点或下划线）就去问 → 否则当本站路径**。
`?` 和 `#` 之后的内容会被丢掉（没有查询串）。

**端点不是地址**：`127.0.0.1:7000/` 这类带冒号的输入会被直接拒绝，而不是默默变成
一个 404 —— 端点只存在于 `nac.routes` 与服务器的回答里。

这是遮掩，不是加密：客户端要直连就必须知道端点，能翻文件的人总能拿到。

## 8. 自己动手试一次

不用客户端也能验证服务端（明文回环最省事）：

```bash
./target/release/contentd --data data --port 7000 --bind 127.0.0.1 &
./target/release/probe --addr 127.0.0.1:7000 hello        # version 5  site nac.local
./target/release/probe --addr 127.0.0.1:7000 health       # ok 27
./target/release/probe --addr 127.0.0.1:7000 resolve shop # shop -> 127.0.0.1:7002 ...
./target/release/probe --addr 127.0.0.1:7000 manifest     # 每页一行：页号 类型 哈希 路径 标题
./target/release/probe --addr 127.0.0.1:7000 page <页号> --path /
```

TLS 站点加 `--tls-pin-file /etc/ssl/nac/public.pin`，地址换成公网端点。
