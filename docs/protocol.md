# 协议手册

线上格式只有一个定义处：[crates/protocol/src/lib.rs](../crates/protocol/src/lib.rs)。
服务端、客户端、`probe` 都从那里取编解码，改一处三端同时变。

---

## 1. 帧

```
┌──────────┬────────┬───────────────┐
│ 4B 长度  │ 1B 类型 │    payload     │
│  big-end │        │               │
└──────────┴────────┴───────────────┘
长度 = 1 + payload.len()，且 ≤ 32768（含类型字节）
```

- 长度 0 或超过上限 → 直接丢弃连接。
- 没有魔数；`HELLO` 请求返回协议版本（当前 3）。v3 的 `MANIFEST` 比 v2 多了路径字段，服务端/客户端必须一起升级。
- 公开站在帧层之下加 TLS（自签证书 + 客户端 pin）；管理端回环可明文。
- 普通请求一连接一请求一响应；`ImageStream` 在同一连接里连续返回多个 `IMAGE` 分片。

## 2. 类型

| 值 | 名称 | 方向 | payload |
|---|---|---|---|
| `0x01` | `REQ` | 客户端 → 服务端 | `16B 会话` + `u8 op` + 参数 |
| `0x02` | `SUBMIT` | 客户端 → 服务端 | `16B 会话` + `u16 页号` + `u16 字段数` + N × (`u8 名长`, 名, `u32 值长`, 值) |
| `0x81` | `MANIFEST` | 服务端 → 客户端 | `16B 会话` + `u16 条数` + N × (`u16 页号`, `u8 标志`, `u64 哈希`, `u16 标题长`, 标题, `u16 路径长`, 路径) |
| `0x82` | `PAGE` | 服务端 → 客户端 | `u16 页号` + `u32 总长` + `u32 偏移` + `u32 本片长` + 字节 |
| `0x83` | `IMAGE` | 服务端 → 客户端 | 同上 |
| `0x84` | `EMPTY` | 服务端 → 客户端 | 16 字节 0 |
| `0x85` | `HELLO` | 服务端 → 客户端 | `u16 版本` |

`REQ` 的 op：

| op | 参数 | 含义 |
|---|---|---|
| `0` | — | 取清单 |
| `1` | `u16 页号` | 取页 |
| `2` | `u16 图号` + `u32 偏移` | 取一个图片分片 |
| `3` | — | 版本握手，返回 `HELLO` |
| `4` | `u16 图号` + `u32 偏移` | 从偏移起在同一连接流式返回全部分片 |

`MANIFEST` 条目的标志位：bit0 = 动态页。`u64 哈希` 是页面内容（动态页用源码，静态页用预渲染输出）的 FNV-1a 64 位值。`路径` 是给读者看的地址（如 `/`、`/notes/`），客户端用它解析地址栏；页号仍是协议内部标识。

## 3. 尺寸与分片

| 项 | 限制 |
|---|---|
| 帧 | ≤ 32768 字节 |
| 页面 | ≤ 16384 字节（发布期与运行期都检查） |
| 图片 | 按 16384 字节分片；旧 `IMAGE` 每次一请求一片，`ImageStream` 一次连接返回全部分片 |
| Python stdout | ≤ 128 KB（超出即判失败） |
| Python 执行 | ≤ 2 秒 |

## 4. 会话

- 16 字节随机值，客户端在 `MANIFEST` 响应里拿到；此后 `REQ`/`SUBMIT` 都带上它。
- 全零表示"我还没有会话"，服务端生成一个并通过 `MANIFEST` 回传，此时会话文件写在
  `state/tmp/` 且**请求结束即删除**（不持久化）。
- 非零会话对应 `state/sessions/<hex>.json`，就是页面里 `nac.session()` 读写的那份。
- 会话只是编号，不是身份：谁抄到它就能接着用，没有任何校验。
- 过期：`--session-ttl-hours`（默认 168），后台线程每 10 分钟清理。

## 5. 错误处理：只有一种失败

**所有**失败——页不存在、脚本崩溃、超时、输出超限、字段畸形、帧解析失败、图片缺失——
都返回**逐字节相同**的 `EMPTY`，连接正常关闭。

理由：如果"页不存在"和"脚本崩了"能区分出来，就等于给探测者一个枚举接口。
原因只进服务端 stderr 与访问日志：

```json
{"t":1792802513,"page":99,"result":"fail","ms":0,"bytes":16,"sess":"b5d18bf9"}
```

`result` 取值：`manifest:N`、`ok:N`（含跳转后的最终页号）、`image`、`image-unknown`、
`image-missing`、`fail`、`malformed`、`no-generation`。

## 6. 服务端如何执行一个页面

1. 读 `data/current` → `data/gen/<代>/manifest.json`（**每次请求都重读**，所以发布新代不用重启）。
2. 页号必须在 manifest 里，文件路径取自 manifest（**不接受客户端提供的路径**）。
3. 起 `python3 -B -X utf8 <scripts/N.py>`，工作目录是代目录，注入环境变量：

   | 变量 | 内容 |
   |---|---|
   | `NAC_PAGE` | 页号 |
   | `NAC_INPUT` | `{"page":N,"fields":{...}}` |
   | `NAC_SESSION_FILE` | 会话文件路径 |
   | `NAC_DATA_DIR` | 站点私有目录 |
   | `PYTHONIOENCODING` / `PYTHONUTF8` | 固定 `utf-8` |
   | `--env K=V` 提供的 | 例如运营台的 `NAC_ROOT` |

4. 捕获 stdout / stderr，各起一个读线程防止管道写满；到点未结束就杀进程。
5. stdout 非空且首个非空白行是 `@@REDIRECT n` → 改发第 n 页（最多一层，防止自跳死循环）。
6. 否则把 stdout 当页面内容返回；超过 16 KB 判失败。

## 7. 寻址：站点目录

客户端不认识 IP，只认识站点名。名字到端点的映射在二进制之外的文本文件里：

```
# 生成一条：viewer --routes-encode 主机:端口
# 检查解码：viewer --routes-check
*home   MTI3LjAuMC4xOjcwMDA=
console MTI3LjAuMC4xOjcwMDE=
```

- 格式：`[*]名字<空白>base64(主机:端口)`；带 `*` 的是默认站点；不含 `:` 时补 `:7000`。
- 查找顺序：`--routes` → `NAC_ROUTES` → **可执行文件同目录** → 当前目录 → 同名 `.example`。
- 地址栏语法：`nac.local/`、`nac.local/about`、`/about`、`about`、`名字.nac.local/about`；旧的 `名字/7`、`nac://名字/7` 仍按内部页号解析；**真实主机地址被拒绝**。

这是遮掩，不是加密：客户端要直连就必须知道端点，能翻文件的人总能拿到。

## 8. 内容标记

服务端不解析页面内容，只负责搬运；解析在客户端（[crates/viewer/src/markup.rs](../crates/viewer/src/markup.rs)）。

| 行首 | 块 |
|---|---|
| `#` `##` `###` | 标题 |
| 空行 | 间隙 |
| `>` | 引用（连续行合成一块） |
| `- ` | 列表（连续行合成一块） |
| `\| ` | 等宽块（连续行合成一块） |
| `!img <id> [pct%] [WxH]` | 图片 |
| `[[2\|文字]]` | 页内跳转 |
| `[[form N]]` | 表单目标 |
| `[[input 名\|提示]]` / `[[secret 名\|提示]]` | 输入框 |
| `[[button 文字]]` | 按钮 |
| `[[cols N]] … [[end]]` / `[[col]]` | 并排布局 |

行内：`*粗*`、`_斜_`、`` `等宽` ``，`\` 转义。

## 9. 为什么不用 HTTP

- HTTP 头会带来一堆不打算支持的东西：来源页、Cookie、`User-Agent`、`Accept-*`、缓存语义，
  每一样都得在"默认拒绝"的立场上重新讨论一次。
- 本项目只需要四个动作：要清单、要页、要图片分片、提交一张表单。自定义帧比 HTTP 短得多，
  也没有"被中间设备按 HTTP 解释"的可能。
- 代价是要自己写全部客户端（约 200 行）与全部服务端（约 600 行），并且没有现成调试工具。
  对一个自用的小系统，这个代价可以接受。

## 10. 已知的取舍

| 取舍 | 说明 |
|---|---|
| 没有流量填充 | 帧长直接暴露内容大小。真在意就得在传输层（Tor 固定 514 字节单元）做，应用层填充无收益 |
| 版本握手不强制 | `HELLO` 返回当前版本，但服务端仍接受旧 op；升级服务器和客户端仍建议一起换 |
| 没有压缩 | 页面 ≤ 16 KB，压不压差别不大；要压就得加算法标识 |
| 没有并发请求 | 普通请求一连接一请求；`ImageStream` 在同一连接顺序返回多片，但仍不是多路复用 |
| 没有认证 | 任何能连上端口的人都能读全部页面、提交任意表单 |
| 直连暴露 IP | 客户端必须知道端点；真正的隐藏属于传输层，当前未实现 |

## 11. 自查命令

```bash
cargo test --workspace           # 帧编解码、标记解析、图片剥离
probe manifest                   # 清单
probe page 1                     # 一页
probe image 1                    # 一张图（自动续取分片）
probe submit 7 name=测试          # 提交一张表单
viewer --selftest                # 客户端侧完整链路
```
