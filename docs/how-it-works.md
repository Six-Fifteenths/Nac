# 它是怎么运作的

这份文档解释 Nac **实际在做什么**。不需要任何背景知识，从「一个 `.py` 文件」讲到
「窗口里出现字」。想看怎么操作去 [start-here.md](start-here.md)；
想看为什么这样设计去 [PROTOCOL-DESIGN.md](../PROTOCOL-DESIGN.md)。

整份文档只围绕一个问题：**你按下 F5，到字出现在屏幕上，中间发生了什么。**

---

## 0. 四件东西

| 东西 | 一句话 | 类比 |
|---|---|---|
| **页面** | `site/` 里的一个 `.py` 文件 | 一页稿子 |
| **publish** | 把整站源码"印"成一代，然后原子地切换过去 | 印刷厂 |
| **contentd** | 一个进程，守着一个端口，把印好的内容递出去 | 书库 + 柜台 |
| **viewer** | 原生窗口，问书库要内容，画出来 | 阅读器 |

它们之间**不用 HTTP**。用的是自己定的一套二进制帧，跑在裸 TCP 上（可以选配 TLS）。

```
                    .py 源码
                       │  publish
                       ▼
              data/gen/<代数>/          ← 印好的一代，之后永不改动
                       │  读
                       ▼
    viewer  ──二进制帧──▶  contentd  ──起进程──▶  python 跑那一页
       │                                              │
       └──────────── 一页标记 ◀───────────────────────┘
```

## 1. 页面是什么

一个页面 = 一个 `.py` 文件。它就是一个普通的 Python 程序，跑起来往标准输出写东西。

```python
# nac:title 留言板
# nac:path /guestbook

import nac

nac.h1("留言板")
nac.p("这一行是正文。")
```

它写出的是这些：

```
# 留言板
这一行是正文。
```

这就是**标记**（markup），不是 HTML。它的文字部分就是 **Markdown** ——
`#` 标题、`**粗**`、`*斜*`、`-` 列表、`>` 引用、三反引号代码块、`|` 表格、
`---` 分隔线 —— 客户端把这些解析成一个个"块"再画出来。

需要页面程序说话的部分（表单、图片、终端、动画、样式）才是 `[[...]]` 指令。
所以"渲染是 Markdown 的超集"是字面意思：**Markdown 怎么写都认，指令只补它做不到的事**。

页面能做普通 Python 能做的一切：`import`、读文件、开 SQLite、连网、起子进程。
它唯一受限的地方是**输出** —— 输出必须是标记，而且有大小上限。

开头带 `# nac:` 的注释是给发布器看的指令：

| 写法 | 作用 |
|---|---|
| `# nac:title 留言板` | 标签页上显示的名字。不写，标签页就是空的 |
| `# nac:path /guestbook` | 这一页的地址。不写就按文件名算 |
| `# nac:static` | 这一页在**发布时**渲染一次，之后不再跑 Python |
| `# nac:match /item/` | 这一页认领一整族地址（`/item/1`、`/item/abc` 全进它） |

## 2. publish 做了什么

`publish --site site --data data` 一条命令，背后是十步：

1. **走一遍 `site/` 目录**，把文件分类：
   - 路径里**任何一段以 `_` 开头**（`_lib/x.py`、`_data/a.json`）→ **素材**，原样复制
     （`_` 开头的 `.py` 只查语法，不当页面）
   - 其它 `.py` → **页面**（带 `# nac:match` 的就是前缀页）
   - `png / jpg / jpeg / webp / gif` → **图片**
   - `bmp / tif / tiff / avif / heic` → **直接报错**，要求先转格式
   - 其余任何文件（`json`、`txt`、`csv`…）→ **素材**，原样复制
2. **检查语法**：用 `compile()` 编译每个 `.py`。有语法错就整个发布失败，一个都不印。
   （文件开头的 BOM 会先被摘掉 —— 那是 Windows 记事本留下的。）
3. **算每个页面的地址**：`index.py` → `/`，`notes/index.py` → `/notes/`，
   有 `# nac:path` 就用它。**两个页面要同一个地址就报错。**
4. **分配页号**：协议里页面用 `u16`（0–65535）标识。页号 = `FNV-1a(地址)` 落在
   `1000..65535` 里，撞了就往后挪一格。**同一地址永远是同一页号** —— 所以页号稳，
   但也不需要你关心，地址才是给人看的。
5. **生成 `nac.py`**：这是发给页面的辅助模块。它里面写死了页号表、标题表、本代代号，
   所以你写 `nac.link_path("/notes/", "笔记")` 时它能在发布期就把 `/notes/` 查成页号。
6. **处理图片**：只剪掉元数据段（EXIF、XMP、注释），**像素逐位不变**，不重编码。
   宽高写进 `nac.py`，客户端拿到尺寸就能在图片到达前把位置留好。
7. **预渲染静态页**：标了 `# nac:static` 的页，在这里跑一次 Python，把输出的标记存成文件。
8. **写 `manifest.json`**：一份清单，每个页面的页号、地址、标题、静态还是动态、内容哈希；
   加上图片清单。
9. **原子切换**：把这一代写进 `data/gen/<Unix秒>/`，全部写完之后，才把
   `data/current` 这个文本文件改成新一代的名字。**改这一行就是"上线"。**
10. **清理**：只留最近 5 代，更早的删掉。

关键点：**第 9 步之前，线上什么都没有变。** 发布中途崩了、语法检查失败了、
磁盘满了 —— 旧的那一代还在正常服务。不存在"发到一半的站"。

```
data/
├─ current               ← 一个文本文件，内容形如 1792940931
└─ gen/
   ├─ 1792940559/        ← 旧的，还在，但没人读
   ├─ 1792940931/        ← 现在生效的这一代
   │  ├─ manifest.json
   │  ├─ scripts/
   │  │  ├─ 65206.py     ← 你写的 index.py，按页号命名
   │  │  ├─ nac.py       ← 生成的辅助模块
   │  │  └─ _lib/…       ← 你的素材，原样
   │  └─ img/…
   └─ …
```

## 3. 你按 F5，发生了什么

按顺序，一棵标签页里：

**① 客户端先拿"整站的目录"。**

它开一条 TCP 连接（开了 TLS 就握手），发一帧 `MANIFEST` 请求，服务端回一帧清单：

```
65206  /               我的第一页
40022  /contact        联系方式
31345  /hi             打个招呼
```

这一帧里还带一个 **16 字节的会话号** —— 客户端第一次发请求时这个字段全是 0，
服务端看到全 0 就新生成一个，随清单发回来。之后客户端一直带着它。

**② 客户端在本地把"地址"变成"页号"。**

`/hi` → `31345`。这一步**不联网**，因为清单已经在手里了。找不到就是 404。

具体规则，按顺序试：

1. 路径完全相等（`/notes/paths` 对上 `/notes/paths`）
2. 加/去尾斜杠后相等（`/notes` 与 `/notes/` 是同一页）
3. 找一个认领了这族地址的前缀页，取**最长**的那个前缀（`/item/42` → 认领 `/item/` 的那页）
4. 路径是 `/` → 用首页
5. 都不成 → 再试能不能当纯数字页号理解（老链接兼容）
6. 还不行 → 「404 · 没有 /xxx」

**③ 客户端请求那一页。**

再开一条 TCP 连接，发 `REQ(页号, 路径)`。**注意路径也一起发** ——
前缀页需要知道自己被问的是 `/item/42` 还是 `/item/7`。

**④ contentd 找到这一页的文件。**

读 `data/current` → 得到代数名 → 读那一代的 `manifest.json` → 查页号 → 拿到文件名。

**⑤ 分两种情况。**

| 页面类型 | contentd 做什么 |
|---|---|
| 静态页 | 直接把发布时存好的那份标记读出来发走。**不起 Python** |
| 动态页 | 起一个 Python 进程跑它，收它的标准输出 |

跑 Python 时的细节（写页面时有用）：

```bash
python -B <页号>.py
# 工作目录 = 那一代的 scripts/    ← 所以 import _lib.x 和 open("_data/x.json") 都能用
# 环境变量：
#   PYTHONUTF8=1      按 UTF-8 处理源码和输出
#   PYTHONIOENCODING  utf-8
#   NAC_PAGE          页号
#   NAC_PATH          读者要的地址，如 /item/42
#   NAC_INPUT         一页 JSON：{"page":…, "path":…, "fields":{…}}
#   NAC_SESSION_FILE  这个会话的数据文件路径
#   NAC_DATA_DIR      站点私有可写目录（data/appdata）
#   NAC_STATIC=1      只在发布时预渲染时出现
```

**⑥ 页面写到标准输出，就是这一页。**

更准确地说：**`import nac` 之后**，`nac.py` 会把 `sys.stdout` 换成 `sys.stderr`，
所以页面里的 `print()` 只进服务端日志，不会跑到读者面前。要输出标记得用 `nac.*`。
（不 `import nac` 的页面，`print()` 出来的东西会原样变成页面内容 —— 但那种页面基本不存在。）

这个设计是为了让调试不危险：`print(变量)` 随时可以加，加完忘了删也不会污染页面。

**⑦ 页面主动"跳转"也能表达。** 输出里有 `@@REDIRECT <页号> <地址>` 时，
contentd 不把它当内容，而是**在同一次请求里**接着去跑目标页，把目标页的内容发回去。

**⑧ contentd 检查并回帧。**

输出的字节数超过 16 KB 就回空响应。正常就回一帧 `PAGE`。

**⑨ 客户端解析成块，画出来。**

`# 标题` → 一级标题块，`- 一项` → 列表块，`[[table]]…[[end]]` → 表格块……
然后按屏幕宽度排版、绘制。

**⑩ 图。**

页面里的 `!img 3 60%` 是"第 3 号图，宽度 60%"。客户端发现手里没这张图，
就单独发一帧要图，拿回来存成纹理。**「一次请求、一页内容」不包括图片** —— 图片是另外取的。

### 什么时候会重新要清单

| 动作 | 重新拿清单？ |
|---|---|
| 按 F5 / 点刷新 | **会**。所以发布完按 F5 就能看到新页面，也包括"新加的那一页" |
| 在本站里点链接跳页 | 不会。清单已经在手里，直接用 |
| 跳到另一个站 | 会。那是另一个服务端，得重新问 |
| 新开标签页 | 会 |

静态页在客户端有缓存，判断依据是清单里的**内容哈希** —— 这一页没改就不重新下载。
所以"F5 重新拿清单"不只是为了看新页面，也是为了让哈希能对比上。

## 4. 数据到底长什么样

一帧就是：

```
u32（大端）长度 = 1 + 负载长度，最大 32768
u8          类型
负载
```

帧头里**没有魔数、没有协议名字、没有版本号**。发一串别的东西进来，解不出来就当畸形，
回一帧空响应然后断开 —— 这正是"指纹"的作用：从外面看它不像任何已知协议。
（协议版本不是放在帧头里，而是 `HELLO` 的回答中带一个 `u16`。）

方向只有两种：

| 客户端 → 服务端 | 说明 |
|---|---|
| `REQ` `0x01` | 会话 16B + 路径 + 操作码 + 参数。操作码：0 清单 / 1 页 / 2 图片片 / 3 握手 / 4 图片流 / 5 解析站点 |
| `SUBMIT` `0x02` | 会话 16B + 路径 + 页号 + 字段列表（键 `u8` 长度、值 `u32` 长度；没有操作码，因为提交就是提交） |

| 服务端 → 客户端 | 说明 |
|---|---|
| `MANIFEST` `0x81` | 会话 16B + 条数 + 每条的 页号/静态标志/哈希/标题/地址/前缀 |
| `PAGE` `0x82` | 页号 + 总长 + 偏移 + 本片长 + 字节 |
| `IMAGE` `0x83` | 同上 |
| `EMPTY` `0x84` | 16 个零字节。**表示"没有"，永远不解释为什么** |
| `HELLO` `0x85` | 版本 + 站点名 |
| `RESOLVED` `0x86` | 名字 + 端点 + 是否 TLS + 标题 |

两条容易漏的事实：

- **一条连接只服务一个请求。** 问完就关，下次再开。（唯一的例外是"图片流"：
  一条连接上连着发很多片。）
- **大东西都是分片的**，每片 16 KB，靠偏移量拼。页面本身不分片（超过 16 KB 直接被拒）。

### 抓一帧看看

真拿一个只有 6 页的站问一次清单，收到的这一帧是这样开的：

```
帧总长 186 字节
  00 00 00 b6       长度字段 = 182（含类型字节）
  81                类型 = MANIFEST
  05 44 08 2b …     会话 16 字节
  00 06             这一代有 6 页
  然后 6 组：页号(2) 静态标志(1) 哈希(8) 标题(2+字节) 地址(2+字节) 前缀(2+字节)
```

所以一个页面在清单里占 `13 + 标题字节 + 地址字节`（前缀为空时）。这个数字后面会用到。

`EMPTY` 是整套设计的核心姿态：**页面不存在、Python 崩了、超时了、站点不认识 ——
全都回同样的空响应。** 外面的人分不清是哪一种，原因只写进服务端日志。

## 5. 输出是标记，不是网页

客户端认识的块就这些（左边是页面里怎么写，右边是什么）：

| 页面里 | 变成 |
|---|---|
| `# 文字` `## 文字` `### 文字` | 三级标题 |
| `一段文字` | 正文段落 |
| `*粗体*` `` `代码字体` `` | 行内强调 |
| `- 项` | 无序列表 |
| `1. 项` | 有序列表（数字会被重排） |
| `> 引用` | 引用块 |
| `---` | 一条横线 |
| `[[code python]]…[[end]]` | 代码块 |
| `[[table]] \| 头 \| … [[end]]` | 表格（第一行是表头） |
| `[[note ok\|标题]]…[[end]]` | 提示框（ok / warn / danger / info） |
| `[[details 标题]]…[[end]]` | 折叠块 |
| `[[cols 2]]…[[col]]…[[end]]` | 分栏 |
| `[[tabs 甲;乙]]…[[tab]]…[[end]]` | 选项卡 |
| `!img 3 60%` / `!cap 说明` | 图片 / 图注 |
| `[[path:/notes/\|文字]]` | 站内链接 |
| `[[url:https://…\|文字]]` | 站外链接（点了交给系统浏览器） |
| `[[form 31345]]` `[[input 名\|标签]]` `[[button 文字]]` | 表单 |
| `[[hidden 名\|值]]` | 读者看不见的状态 |
| `[[prefill 名\|值]]` | 给字段一个初始值（只在没动过时生效） |
| `[[scene 640x240 4]]` `[[bar 颜色 宽 高]]` `[[at 秒 x y]]` `[[end]]` | 一段动画，见下 |
| `[[term panel\|标题\|页号]]` `[[line 角色\|文字]]` `[[cursor 名\|…]]` `[[end]]` | 一块终端面板，输入框在框里 |
| `[[sheet]] .c { bg: #fff; } [[end]]` + `[[box class=c]]…[[end]]` | 样式层：盒子与类，只有「是什么」，没有「多大」，见 authoring 第 11 节 |
| `[[avatar 名字 28]]` | 头像：名字算颜色，首字母上图，不联网 |

**没有 CSS，没有 JavaScript。** 理由很实际：页面是 Python，在服务端跑；
要让浏览器里也跑代码，就得再实现一个语言和一个引擎，那是另一个项目。

因为排版由客户端决定，**同一个页面在窄窗口和宽窗口里都好看**，不需要写媒体查询。
代价是：你没法精确控制像素级的样子。这是刻意的。

### 动画是怎么动的

`[[scene]]` 的一页这样写（可以直接用 `nac.raw()` 把这几行原样发出去）：

```
[[scene 640x240 4.06]]      画布 640×240，总长 4.06 秒
[[bar 6b7280 8 176]]        一根 8×176 的灰条
[[at 0 106 34]]             第 0 秒，在 (106, 34)
[[bar c0392b 176 16]]       一根 176×16 的红条
[[at 0.00 22 192]]          第 0.00 秒
[[at 0.19 22 34]]           第 0.19 秒
[[at 0.43 428 34]]          第 0.43 秒
[[at 0.58 428 192]]         第 0.58 秒
[[end]]
```

一个 `[[bar]]` 是一块矩形（颜色、宽、高），后面跟它的 `[[at]]` 关键帧（秒、x、y）。
客户端拿到的是**关键帧，不是画面**：它在两帧之间做缓入缓出（smoothstep）插值，
每帧重画，到最后一帧停住。点一下画面从头播。

于是「60 帧的动画」只花了**一次**服务端请求和几百字节 ——
服务端不需要一帧一帧地算，也不需要保持连接。汉诺塔就是这么做的：
页面只算出"每个盘子在什么时候到哪个坐标"。

## 6. 表单：一次往返

页面里写：

```python
name = nac.field_of("name")     # 有人提交过就有值，没有就是 ""
nac.form_path("/hi")           # 提交到哪一页
nac.field("name", "你的名字")
nac.button("说你好")
```

读者点按钮时：

1. 客户端把表单里填的值收成一串键值对
2. 发一帧 `SUBMIT(页号, 路径, 字段列表)`
3. 服务端**重新跑一遍那一页的 Python**，这次 `NAC_INPUT` 里带着字段
4. 页面看到 `nac.field_of("name")` 有值，就换一段输出
5. 服务端回一帧 `PAGE`，客户端整页替换

也就是说：**表单没有"局部更新"**。提交就是"带着数据重新要这一页"。
简单、无状态、不需要任何前端框架。

想要"提交完跳走"：

```python
nac.redirect_path("/guestbook")
```

这会输出一行 `@@REDIRECT <页号> /guestbook`，contentd 看到就**在同一次请求里**
接着跑目标页，把目标页的内容回给客户端。**最多允许一跳**，第二跳当死循环拒掉。

### 会话

页面要记住"这个人上次填了什么"，用会话：

```python
nac.session_set("name", "阿离")     # 写
saved = nac.session_get("name")     # 读
```

会话号是 16 字节，由服务端在第一次 `MANIFEST` 时生成并交给客户端。
客户端只在内存里存着，关掉窗口就没了。服务端把它**落成一个 JSON 文件**：

```
data/state/sessions/<32位十六进制>.json
```

默认 168 小时没动过就删，每 10 分钟扫一遍。**没有 cookie，没有浏览器存储** ——
"会话"就是一个文件名。

## 7. 地址是怎么找到机器的

地址栏里写 `iris.out/entry/blue`，分两半：**名字** `iris.out`，**路径** `/entry/blue`。

名字就是**一整串字符**。没有层级、没有"公共后缀"、不参与任何推导。
`nac.local` 和 `EX_MYTH` 地位完全平等。合法字符只有字母、数字、点、连字符、下划线，
最长 64 字节；**含冒号或方括号直接被拒**（那是在输入 IP:端口，不是在输地址）。

客户端手里有一份**种子表**，一行一个：

```
*nac.local  MTk5LjcuMTQwLjIxNzo3MDAw   tls
```

（第二列是 base64 过的 `主机:端口`。这只是防一眼看穿，不是加密 ——
能翻文件的人总能拿到。客户端必须知道连哪台机器，这是直连的代价。）

遇到表里没有的名字，它不报错，而是**问当前所在的服务器**：

```
客户端在 nac.local，地址栏要 iris.out
  → RESOLVE "iris.out"
  → 服务器查自己的 sites.json
  → 回答: 199.7.140.217:7003, tls, 标题 "iris.out"
  → 客户端记住（只在内存里），连过去
```

这个回答**任何服务器都能给**，不是只有中心能给 —— 每个站都读自己那份 `sites.json`。
所以同一套代码既能做"一台机器上几个站"，也能做"网络里的一个节点"。

查表不分大小写：敲 `ex_myth` 也能进，服务器会回注册表里的写法 `EX_MYTH`，
地址栏随之变成那个写法。

### 一个站 vs 多个站

**每个站是一个独立的进程**，自己的端口、自己的 `data/`、自己的系统用户、自己的沙箱。
它们之间没有共享内存、没有共享数据库，能看到的对方只是注册表里那几行地址。

```
一台服务器上：
  contentd --name nac.local      --port 7000 --data /srv/nac/data
  contentd --name shop.nac.local --port 7002 --data /srv/nac-shop/data
  contentd --name iris.out       --port 7003 --data /srv/nac-iris.out/data
  contentd --name EX_MYTH        --port 7004 --data /srv/nac-EX_MYTH/data
```

一个站挂了不影响别人；一个站的数据另一个站读不到。
所谓"多站点"，物理上就是"多开了几个进程"。

## 8. 那些数字，以及为什么是这些数字

| 数字 | 是什么 | 为什么 |
|---|---|---|
| **32768** | 一帧的最大长度 | 定长上限让解码可以"先看长度再分配"，不给别人用超长帧耗尽内存的机会 |
| **16384** | 一页正文的最大长度 | 一页超过 16 KB 基本说明该拆页了；也让分片逻辑只有"一片"这一种情况 |
| **2 秒** | 一个页面能跑多久 | 超时就杀掉进程回空响应。防止一个死循环卡住一个连接 |
| **128 KB** | 页面标准输出的采集上限 | 超过就截断并判失败，不让页面把内存写爆 |
| **32** | 同时处理的连接数 | 超了就拒；服务端不排队，排队的代价是延迟不可预测 |
| **16 字节** | 会话号 | 够长，正常不会撞；够短，能塞进每一帧 |
| **5 代** | 保留多少个历史版本 | 回滚够用，磁盘可控。每一代都是完整一份，素材多时占地方 |
| **7000 起** | 端口 | 只是约定：主站 7000，运营台 7001，其余站 7002 往上 |

还有一条不是数字但同样硬的限制：**清单本身也受 32768 限制**。
上面算过，一个页面在清单里大约占 `13 + 标题字节 + 地址字节`。20 字标题（60 字节）加短地址约 78 字节，
所以**单站 400 多页就顶到天花板了**（实测 400 页能读，419 页读不到）。
页面再多，客户端连"目录"都拿不到 —— 这时候该拆成两个站，而不是继续加页。

## 9. 出错的时候

| 出了什么事 | 客户端看到 | 真正原因在哪 |
|---|---|---|
| 服务端没起 / 端口不通 | 「无法连接到服务器」 | 进程/防火墙 |
| 名字没人认识 | 「找不到站点 xxx」 | `sites.json` 里没有，或拼错 |
| 地址没有对应页 | 「404 · 没有 /xxx」 | 没有那个 `.py`，或 `# nac:path` 不同 |
| 页面 Python 报错 | 「无法获取内容」 | **服务端日志**里的 traceback |
| 页面跑超过 2 秒 | 「无法获取内容」 | 服务端日志里写着 timeout |
| 页面输出超过 16 KB | 「无法获取内容」 | 内容太长，该拆页 |
| 发布时语法错 | 发布直接失败，终端里有文件名和行号 | 你的代码 |

**记住这条**：窗口上只会说"没有内容"。**原因在服务端，永远在服务端。**
起 contentd 时加 `--log access.jsonl`，或者直接看它那个终端窗口。

## 10. 安全边界：挡得住谁

**挡得住"读者"**：

- 内容只在专用客户端里看得见，搜索引擎爬不到、没有可分享的网址
- 页面失败一律空响应，不泄露"这一页存在但崩了"
- 帧解码全部带边界检查，超长直接断连
- contentd 拒绝以 root 运行；页面脚本继承它的权限，所以这一步是根
- 每个站一个系统用户 + systemd 沙箱：文件系统只读、只有自己目录可写、看不到运营台
- TLS 用自签证书 + **指纹固定**：客户端只认那一张证书的 SHA-256，中间人换不了

**挡不住"作者"**：

页面代码能起子进程、读服务器上任意文件、连外网。它是**你的**代码，跑在**你的**服务器上，
拥有 contentd 那个用户的权限。所以：

> 只跑你自己写的页面。想让别人投稿，得先加隔离（容器、seccomp、只读挂载）。

明确知道且没做的：没有按 IP 限速；`data/appdata` 没有配额，灌数据能把盘写满；
会话号可以伪造，服务端会为未知会话建文件；公开站必须绑 `0.0.0.0` 才能被访问，
所以服务器 IP 必然暴露；站点解析没有签名，服务器理论上可以指挥客户端去连任意地址。

在所有站都是你自己的前提下，这些都不是问题。要做"另一个互联网"，它们就是问题。

## 11. 它不是什么

| | Nac | 网页 |
|---|---|---|
| 传输 | 自定义二进制帧，裸 TCP（可选 TLS） | HTTP |
| 页面 | 服务端的一个 Python 程序 | HTML 文件 + 客户端脚本 |
| 排版 | 客户端按块排版 | 服务端给样式，浏览器执行 |
| 交互 | 提交 → 整页重新要一次 | JS 局部更新 |
| 地址 | 名字（整串字符，无层级） + 路径 | 域名（分层） + 路径 |
| 客户端 | 必须装这个程序 | 任何浏览器 |
| 谁在跑代码 | **服务端** | 服务端 + 客户端 |
| 找机器 | 问任意一个服务器 | DNS 委派 |

它**不是**一个通用 Web 服务器，**不是** HTTP 的封装，**也不是**浏览器插件。
它是一个自成一体的小平台：自己的协议、自己的标记、自己的客户端、自己的名字空间。

## 术语表

| 词 | 意思 |
|---|---|
| **页** | `site/` 里的一个 `.py`，对应一个地址 |
| **站点（站）** | 一个 contentd 进程 + 一个数据目录 + 一个名字 |
| **一代（generation）** | 一次 publish 的完整产物，目录名是 Unix 秒。不可变 |
| **`current`** | 一个文本文件，写着"现在用哪一代" |
| **页号** | `u16`，协议里用来指页面。由地址哈希得来，稳定但你不用管 |
| **清单（manifest）** | 那一代的目录：页号、地址、标题、静态标志、哈希、图片 |
| **前缀页** | 认领一族地址的页（`# nac:match /item/`），自己从 `NAC_PATH` 取参数 |
| **静态页** | 发布时渲染一次，之后不跑 Python；在它里面调会话/数据接口会直接报错 |
| **素材** | 不是页面的文件，原样复制到 `scripts/`，页面照常 `import` / `open` |
| **会话** | 16 字节号，服务端落成一个 JSON 文件 |
| **注册表（`sites.json`）** | 名字 → 端点。每个站一份，用来回答 RESOLVE |
| **种子表（`nac.routes`）** | 客户端内置的"先查这里"，查不到再问服务器 |
| **pin** | 证书的 SHA-256，编进客户端，只认这一张 |
| **EMPTY** | 16 个零字节，"没有内容"，不解释原因 |
